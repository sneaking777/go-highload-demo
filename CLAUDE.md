## О проекте

**go-highload-demo** — демонстрационный Notification Service на Go, имитирующий высоконагруженный сервис рассылки уведомлений. Цель — продемонстрировать навыки работы с многопоточностью (горутины, каналы, sync-примитивы) и highload-паттернами в Go.

## Функциональность

Сервис принимает запросы на отправку уведомлений и параллельно рассылает их по разным каналам (email, push, SMS, webhook).

Ключевые паттерны:
- **Worker pool** — настраиваемый пул воркеров на каналах
- **Fan-out** — одно событие → параллельная отправка в несколько каналов
- **Backpressure** — буферизированные каналы, контроль перегрузки
- **Graceful shutdown** — корректное завершение через context + WaitGroup
- **Rate limiting** — ограничение частоты отправки
- **Retry с exponential backoff** — повторные попытки при сбоях

## Стек технологий

- **Язык**: Go
- **БД**: PostgreSQL (хранение уведомлений и статусов)
- **Очередь сообщений**: RabbitMQ (очередь уведомлений, routing, dead letter queue)
- **Кэш / Rate limiting**: Redis
- **Инфраструктура**: Docker Compose (всё в контейнерах, включая Go)
- **Нагрузочное тестирование**: k6 / vegeta
- **Профилирование**: pprof

## Команды для разработки

```bash
# Запуск всех сервисов
docker compose up -d

# Запуск только приложения (с hot reload через air)
docker compose up app

# Тесты
docker compose exec app go test ./...

# Нагрузочное тестирование
docker compose run k6 run /scripts/load-test.js

# Профилирование
go tool pprof http://localhost:8080/debug/pprof/goroutine
```

## Методология разработки

Разработка ведётся по **BDD + TDD**:
1. **BDD** — сначала описываем поведение фичи (что система должна делать с точки зрения пользователя/API)
2. **TDD** — пишем тесты до реализации (Red → Green → Refactor)
3. Для каждого компонента: сначала тест, потом минимальная реализация, потом рефакторинг
4. Тестовые фреймворки: стандартный `testing` + `testify` для ассертов и моков
